#+title: t3-code.el

T3 Code in Emacs: a Markdown chat buffer, a plain-text input buffer, and
conversations tied to your projects and worktrees. Inspired by
[[https://github.com/dnouri/pi-coding-agent][pi-coding-agent]].

* Setup

Use the [[https://github.com/ArthurHeymans/t3code/tree/EverythingArthur][EverythingArthur branch of my T3 Code fork]]. It includes the
=t3 client --stdio= bridge this client needs.

Add this checkout to =load-path= and load the client:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/emacs-t3-code")
(require 't3-code)
#+end_src

Put that fork's =t3= executable in =exec-path=. If running from a source
checkout instead, set the bridge command:

#+begin_src emacs-lisp
(setq t3-code-bridge-command
      '("node" "/path/to/t3code/apps/server/src/bin.ts" "client" "--stdio"))
#+end_src

With the T3 Code server running, issue a token on the server host:

#+begin_src sh
t3 auth session issue --label emacs --token-only
#+end_src

Run =M-x t3-code= and paste the token when prompted. After connecting, it
offers to save the token in =auth-source= for next time.
Use =M-x t3-code-connect-prompt= to connect to a different server.

* Using it

Run =M-x t3-code= from a project to open its conversation. Outside a known
project, or with =C-u=, it opens the thread ledger instead.

Write in the input buffer and press =C-c C-c= to send. While the agent is
working, this queues a follow-up; =C-c C-s= steers the current turn instead.
Click the model or reasoning effort in the input header to change it.

=TAB= completes slash commands, =$skills=, =@project-files= and file paths.
=M-p= / =M-n= recall previous prompts. In the chat, =TAB= expands folded
tool calls and reasoning, and =RET= opens files and links or answers a
pending question. Scroll back to read history; =G= resumes following output.

New threads can use the project root, a new worktree or an existing one.
The chat buffers use that directory too, so ordinary Emacs file and project
commands work where the agent is working. Remote files are visited through
TRAMP; the bridge runs locally.

| Key       | Action                                 |
|-----------+----------------------------------------|
| =C-c C-c= | Send or queue (input)                   |
| =C-c C-s= | Steer (input)                           |
| =C-c C-k= | Abort                                  |
| =C-c C-p= | Thread menu (input); =?= in chat        |
| =C-c C-m= | Select model                           |
| =C-c C-n= | New thread                             |
| =C-c C-j= | Switch thread                          |
| =C-c C-b= | Thread ledger                          |
| =f=       | Fork at the current turn (chat)         |
| =o=       | Load older history (chat)               |
| =q=       | Hide chat and input (chat)              |

Hiding a conversation does not stop the agent. Command output appears in
the chat, not a live terminal.

* Development

=M-x t3-code-demo= runs without a server, using the fake bridge.

#+begin_src sh
make check         # byte-compile and ERT tests
make check-t3code  # also test the adjacent T3 Code bridge
#+end_src

See the [[file:docs/protocol-v1.md][bridge protocol specification]] for implementation details.
